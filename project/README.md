# OpenAI OAuth 账号工具

本项目是在本机运行的 OpenAI OAuth 账号工具，直接调用 `https://coding.tu-zi.com` 现有管理接口完成后台账号创建，或为后台已有的 OpenAI OAuth 账号重新授权。设置页使用后台登录邮箱和密码建立会话；添加账号和重新授权默认按邮箱从本机号池自动取得登录材料，完整密码 + 2FA 优先，否则使用邮箱取件 Token。号池同时返回两个非空的密码和 2FA 字段时，工具先按原顺序提交；只有 OpenAI 明确返回密码凭据错误时才交换两者再试一次，反转候选不受字段长度或预判格式限制，其他错误不会触发交换。添加账号的代理、并发数、供应商和分组来自后台选项；重新授权默认沿用目标账号现有代理，也可以显式选择“无代理”让本次任务直连。

工具不会向页面返回、展示或持久化后台 Token、OpenAI Refresh Token、Access Token、ID Token、OAuth code、state 或完整兑换结果。

## 环境要求

- macOS
- Node.js 24 或更高版本
- 已安装 Google Chrome；OpenAI 授权固定用一次性临时配置直接启动无痕式窗口，不读取日常 Chrome Profile
- 可访问 `coding.tu-zi.com`、OpenAI 登录页和固定邮箱接口
- 拥有目标管理后台的有效账号和账号管理权限

## 安装与启动

```bash
npm install
npm run build
npm start
```

默认配置只监听 `127.0.0.1:43123`。当前本机 LaunchAgent 另外启用了受限局域网 HTTP 入口 `http://192.168.50.218:43123/`：它只绑定这个精确 IP，只接受 `192.168.50.0/24` 的 TCP 客户端，不绑定 `0.0.0.0`。`43123` 不会代理或暴露环回 `/internal/account-materials`；中央号池是另一个进程，按当前部署另外精确监听 `http://192.168.50.218:3001/`。

两个 LAN 入口按用户明确取舍使用明文 HTTP。`43123` 链路会承载本地工具会话、账号密码和验证码；中央号池 `3001` 链路还会承载配对码、长期设备 Bearer Token、账号密码、2FA 密钥、邮箱取件材料、后台身份摘要、任务选项和结果。Host 与 CIDR 校验只限制可达范围，不提供传输加密。只能用于可信隔离局域网，不应连接访客网络或不可信 Wi-Fi；正式多机部署仍建议升级 HTTPS。

当前环回 HTTP 和局域网 HTTP 都可以直接打开固定地址，不需要先取得或更换单次链接：

```text
http://127.0.0.1:43123/
http://192.168.50.218:43123/
```

页面首次请求精确的 `GET /local-api/session` 时，服务自动签发有效期一年的 HttpOnly 本地会话 cookie，并返回页面需要的 CSRF。其他未认证读取和全部写请求不会自动建会话，仍受 Cookie、精确 Origin 和 CSRF 保护。正常 API 使用会重新签发同属性 cookie，使有效期从本次使用起自动延长一年；普通服务重启不会使当前浏览器失效。

每次启动仍会分别打印环回和局域网的备用单次访问链接：

```text
http://127.0.0.1:43123/bootstrap?nonce=<one-time-value>
http://192.168.50.218:43123/bootstrap?nonce=<one-time-value>
```

这些链接保留给 LAN HTTPS 模式和诊断回退。打开完整链接后，页面会先通过同源 `/healthz` 检查当前连接和服务状态，检查成功后自动提交一次性入口并跳转首页；检查失败时不会消费链接。环回、LAN HTTP 和 LAN HTTPS 使用不同的 Cookie/会话边界，不能互换；只有 HTTPS 模式的局域网 cookie 强制 `Secure`。不要改用 `localhost`，页面即使被手动打开到 `localhost` 也会自动切回 `127.0.0.1`。

局域网设备访问：

1. 直接打开 `http://192.168.50.218:43123/`，不需要安装 CA、复制启动 nonce 或更换链接。
2. 页面加载时自动建立当前浏览器的 LAN HTTP 会话。远端页面只负责操作本机服务，OpenAI 授权 Chrome 仍在 `192.168.50.218` 这台 Mac 上启动。

### 中央号池协同

号池系统的“上号系统”支持每个操作者绑定自己的 Mac。中央号池只保存设备归属、脱敏任务和记录锁；每台 Mac 运行独立的 `43124` 后台助手并主动长轮询中央地址，因此别人从自己的号池账号启动任务时，无痕 Chrome 会在其选中的 Mac 上打开，不再固定使用服务器所在 Mac 的后台账号和浏览器。独立助手不依赖、控制或复用 `43123` 进程。

首次安装助手：

```bash
../queue-management/helper/scripts/helper/install-macos.sh http://192.168.50.218:3001
```

安装脚本要求 Node.js 24+ 和 `/Applications/Google Chrome.app`，构建 `../queue-management/helper/dist/helper/index.js`，把版本化运行目录安装到 `~/Library/Application Support/up-icloud-helper/`，并注册独立 LaunchAgent `com.up-icloud.provisioning-helper`。助手只监听 `127.0.0.1:43124`；中央 origin 在安装时固定，不能由网页临时改成其他站点。

号池用户在 `3001` 的“上号系统”点击“连接这台 Mac”后，页面创建五分钟有效、当前用户所有、单次使用且绑定当前号池 origin 的连接意图，再用顶层表单 POST 到本机助手。连接凭据不进入 URL、浏览历史或 referrer。助手自己生成设备 Token，中央只保存 SHA-256 哈希；原始 Token 只进入该 Mac 的 `up-icloud-helper.provisioning-agent` Keychain 项。连接完成后页面自动核对设备归属并选中，不需要复制配对码。“手动配对”只作为旧 `43123` 备用流程保留。

旧 `43123` 助手已经配对后，可以在设置页点击“更换地址”，把同一中央号池从环回地址切换到局域网地址，或切换到该号池的另一个可达 origin。服务会先使用现有设备 Token 请求新地址并核对设备 ID；只有确认仍是同一设备才保存和恢复轮询。验证失败、目标是其他号池或任务正在执行时不会覆盖原地址，也不要求重新输入配对码。

第一次连接如果尚未登录兔子后台，助手窗口只显示兔子后台邮箱、密码和必要的 TOTP 输入。后台 Refresh Token 保存在独立的 `up-icloud-helper.coding-session` Keychain 项，不读取或覆盖 `43123` 使用的 `up-icloud.coding-session`。助手的本地会话保存在 HttpOnly、SameSite Strict、最长一年的环回 Cookie 中；密码和 TOTP 不进入 Cookie、SQLite 或日志。后续正常使用直接复用该 Mac 的助手与后台会话。

中央任务按号池记录一次性取得密码、2FA 和邮箱取件材料，再沿用本工具已有的自动选择规则：完整密码 + 2FA 优先，否则使用邮箱取件 Token。任务只落库加密材料的版本化 keyed HMAC 指纹，材料本身只在当前任务作用域存在，不进入中央浏览器、两边任务历史或日志。

Mac 必须在独立助手的后台会话已恢复且已认证时才领取任务，并在取材料和开始后台写入前由中央再次校验。`43124` 使用自己的 SQLite、任务编排器和唯一执行槽，与 `43123` 的本地任务完全隔离。用户取消、权限撤销和后台写入之间有中央 `begin-write` 原子门禁：未领材料且未开始写入的任务可直接取消解锁；已领材料但未写入的任务保留锁并由原 Mac 收敛；已开始写入的中断结果标记为不确定，不自动重试。断开设备时必须先由中央确认该设备没有活动任务，本机才删除 Keychain Token。

为了避免网络分区下重复写后台，已领材料的任务不设自动租约转移。如果原 Mac 永久离线或丢失设备 Token，任务和号池记录锁可能长期保留，需恢复原 Mac 后上报结果或人工核对后处理，不应直接重做。

助手升级会在没有活动任务时保留上一版本并重启 `com.up-icloud.provisioning-helper`；`../queue-management/helper/scripts/helper/rollback-macos.sh` 切回上一版本，`../queue-management/helper/scripts/helper/uninstall-macos.sh` 只移除新助手 LaunchAgent并保留数据、日志和 Keychain 凭据。三个脚本都不会停止、修改或删除 `com.up-icloud.local`。原 `http://127.0.0.1:43123/` 与受限 LAN 入口继续完整保留，可以独立执行添加账号和重新授权，作为完整备份。

可用环境变量：

- `PORT`：本地监听端口，默认 `43123`。
- `APP_DATA_DIR`：本地数据目录，默认 `~/Library/Application Support/up-icloud`。
- `WEB_ROOT`：生产前端目录，默认 `<项目目录>/dist/web`。
- `ACCOUNT_POOL_BASE_URL`：本机号池 bridge 地址，默认 `http://127.0.0.1:3001`，只接受环回 HTTP origin；设置页已连接远端纯号池时不会使用该 fallback。
- `ACCOUNT_POOL_BRIDGE_TOKEN`：号池只读 bridge token，至少 32 字节。
- `ACCOUNT_POOL_BRIDGE_TOKEN_FILE`：bridge token 文件；默认 `<APP_DATA_DIR>/account-pool-bridge-token`。
- `ACCOUNT_POOL_TIMEOUT_MS`：号池查询超时，默认 `5000`，范围 `500` 至 `30000` 毫秒。
- `LAN_ACCESS_ENABLED`：是否启用第二个局域网监听，只接受 `true` 或 `false`，默认关闭。
- `LAN_PROTOCOL`：局域网入口协议，只接受 `http` 或 `https`；未设置时默认 `https`。当前 LaunchAgent 明确设置为 `http`。
- `LAN_HOST`：要绑定的本机私有 IPv4，必须属于当前活动网卡和允许网段。
- `LAN_ALLOWED_CIDR`：允许访问的规范私有 IPv4 CIDR；整个网段必须位于私有地址空间，且必须包含 `LAN_HOST`。
- `LAN_TLS_CERT_FILE`：只在 `LAN_PROTOCOL=https` 时必需；服务器证书绝对路径，SAN 必须包含 `LAN_HOST`，必须在有效期内并与私钥匹配。
- `LAN_TLS_KEY_FILE`：只在 `LAN_PROTOCOL=https` 时必需；服务器私钥绝对路径，必须是小型普通文件，group/other 权限必须全部关闭。

后台基地址固定为 `https://coding.tu-zi.com/api/v1`，不能通过页面或环境变量改成其他地址。

## 使用流程

1. 打开“设置”，输入后台登录邮箱和密码，点击“登录后台”。
2. 如果后台要求 TOTP，页面再显示六位动态验证码输入；否则直接完成登录。
3. 设置页的“可信邮箱服务”会显示不可删除的内置路径式邮箱 origin，其中包括 `icloud-api.top`、`mail.mczero.top`、`blog.tx.sb` 和 `webmail.503.me`。`icloud-api.top` 同时支持专用 `/show/<访问凭据>/<邮箱>` 页面。需要使用另一个 `/s/<访问凭据>/<邮箱>` 服务时，先在这里添加它的域名或 HTTPS origin；保存后后续任务立即生效，不需要重启。`email.lzg666.icu` 由固定 `/code/<访问凭据>` 专用适配器管理，不需要在这里配置。活动任务期间不能修改该列表。
4. 密码和 TOTP 每次提交后都会立即从页面清空。登录成功后，只把后台签发的 Refresh Token 保存到 macOS Keychain 的 `up-icloud.coding-session` 项。
5. 打开“添加账号”，输入 OpenAI/iCloud 登录邮箱。“账号池自动获取”默认开启，不需要选择密码或邮箱验证码，也不需要再次填写密码、2FA 或邮箱 Token。
6. 纯号池模式连接 `http://192.168.50.207:3000` 时，只填写号池地址并点击“打开并检查网页状态”。43123 使用固定的 `account-pool-profile` 专用持久 Chrome 打开号池网页，不要求在 43123 设置页输入号池账号密码；用户在该窗口完成免密登录后再次检查即可。登录状态以同一网页会话中的 `/api/me` 为准，任务也通过该会话按规范化邮箱查询远端账号列表，再按记录 ID 读取密码、2FA 和邮箱 Token。Cookie 不会复制到 Node、Keychain、前端、SQLite 或日志，断开连接也不会删除该 Chrome Profile，因此下次可以继续复用网页登录状态。号池登录失效、邮箱不存在或材料不完整时，在打开 OpenAI 前停止。未配置远端纯号池地址时，才使用本机 `127.0.0.1:3001` 的环回 bridge 兼容路径。两种材料都存在时仍优先密码 + 2FA；只有明确切换到“手动备用”后，页面才显示原来的手动输入框。
7. 选择代理方式、并发数、可选供应商和可选分组。“清除所有模型”固定启用。
8. 开始任务后，工具先解析号池材料，再解析代理、调用后台原接口实时生成授权链接，并打开独立可见的 Google Chrome 无痕窗口。无代理及无需浏览器代理认证的任务通过 macOS Launch Services 以非激活方式启动，窗口保持可见但不会主动夺取键盘焦点；临时 Profile 与调试端口共同锁定任务 Chrome 的真实进程，任务结束时只关闭该实例。必须由 Playwright 处理代理认证的任务保留兼容启动路径，并以精确进程 ID 快速恢复原前台应用。自动选择邮箱验证码时会在此之前建立邮箱基线；自动选择密码 + 2FA 时完全不访问邮箱接口。
9. 邮箱验证码模式最多执行三个各 60 秒的取件轮次。FlySMS 固定 API 明确返回 `ACCOUNT_EXPIRED` 时，重新授权任务会在打开 Chrome 前停止，并只给已锁定后台账号的现有名称追加一次“（邮箱接码过期）”；普通 401/403、Token 无效、空收件箱、临时网络错误或其他邮箱来源不会触发该写入。第一轮和第二轮没有可靠结果时，任务页会分别提醒并在确认仍处于 OpenAI 验证码页后自动点击一次精确识别的重发控件；整个任务最多自动重发两次。每次重发前都会刷新邮箱状态，但后续轮次继续使用任务开始后的新邮件边界，因此重发复用相同验证码或更新原邮件时不会把仍有效的验证码误判为任务前旧邮件。若用户恰好先点击重发、按钮状态随之变化但页面仍是可信验证码页，工具会继续下一轮，不会立即接管。第三轮仍无可靠结果、邮件顺序不可信或页面无法安全识别时，工具会保留无痕窗口并进入人工接管。
10. 密码 + 2FA 模式按顺序自动填写账号邮箱和号池中的账号密码；严格识别到认证器动态码页面后，由本地服务使用号池中的 2FA 密钥生成六位动态码。当前动态码剩余不足 10 秒时等待下一周期；第一次提交后只有同一页面仍明确要求认证器动态码时才允许再提交一个后续周期动态码，总计最多两次。密码不会自动重复提交，也不会在拒绝后自动切换邮箱验证码。
11. 取得邮箱验证码或生成认证器动态码后，工具只在用途明确的页面填写对应验证码，并在严格识别到 Codex 授权同意页后点击“继续”。若精确 `https://auth.openai.com/add-phone` 页面同时出现唯一电话输入框、手机号码必填/发送验证码文案和“继续”控件，重新授权任务会停止自动化、关闭任务无痕窗口，并只给已锁定后台账号名称追加一次“（手机接码）”；不会自动填写或提交手机号码。其他 MFA、普通电话文字或不完整表单仍进入人工接管，不修改名称。自动提交遇到尚未覆盖的页面时会保留同一个无痕窗口并进入人工接管。手动跨过当前步骤后，工具会识别邮箱、密码、邮箱验证码、认证器 2FA 或 Codex 同意页，并从当前页面自动接回后续流程；人工流程打开新标签页或弹窗时会跟随新的顶层页面。如果任一受控标签页已经产生合法回调，则直接继续兑换。
12. 遇到 CAPTCHA、用途不明的六位码、Passkey、安全密钥、短信、恢复码、账号选择、风控或未知页面时，在授权浏览器中手动完成；工具不会绕过安全挑战，也不会猜测应使用邮箱码还是认证器动态码。接管监听只把真实按钮操作、表单提交、回车、主页面跳转（包括跳转后仍是相同路径）或进入新的已知步骤视为人工进展，页面动画和倒计时不会触发重复自动化。
13. 页面跳转到本机回调后，工具直接捕获回调并使用原授权会话兑换，不需要人工复制 URL 或 Code；兑换成功后创建账号，并只显示后台账号 ID、名称、状态和所选配置。任务成功、失败、取消或浏览器明确关闭后，工具会关闭本次任务创建的无痕 Chrome 并删除对应临时配置，不影响用户日常 Chrome。

如果 OpenAI 页面明确显示完整错误码 `account_deactivated`，工具会使用全新的 OAuth 会话重复完整登录确认。设置页可将“自动封号确认”配置为 `1-10` 次，默认 `2` 次；当前任务启动时会锁定当时的设置值，连续达到该次数且能按任务锁定 ID 或规范化邮箱唯一确定后台 OpenAI OAuth 账号时，才把该账号标记为“封号”。设置为 `1` 次时首次精确检测后直接进入封号处理；模糊文案、确认未连续完成、账号缺失或同邮箱多条记录都不会写后台状态。封号更新只发送一次，并以独立账号详情查询作为成功依据，网络或响应不确定时不会重放写入。

“重新授权”是左侧的独立入口，不会创建新账号：

页面右侧提供“开始托管”。托管会锁定当前搜索、7 天用量阈值、导入时间和代理模式，按筛选结果逐个执行；成功、普通失败或启动前资格变化后都会继续下一个账号。遇到人工接管时暂停等待，人工处理完成后自动续跑。“跳过当前”会取消仍可取消的当前任务、计入跳过并继续下一个；OAuth 写回等不可取消阶段会拒绝跳过。“停止托管”只停止后续账号，不取消当前正在处理的任务。

1. 页面提供 `0-100` 的整数阈值输入，默认 `90`；只显示后台错误状态且 7 天用量不高于当前阈值的 OpenAI OAuth 账号，并支持按名称或邮箱搜索和分页。修改阈值会清空当前选择并按新条件重新加载，页面不提供“全部账号”入口。
2. 选择账号后，页面再次读取后台详情并锁定账号 ID 与邮箱；邮箱不能手工修改。
3. 锁定邮箱会直接用于号池精确查询，不需要选择登录方式或填写材料；只有显式切换到“手动备用”时才显示原输入。该页面不显示代理、并发数、供应商、分组、重复创建、混合渠道或模型选项。
4. 授权登录、验证码、同意页和回调流程与添加账号共用。代理策略只有“原账号代理”和“无代理”：默认沿用原账号代理；显式选择“无代理”时，本次授权 URL、无痕 Chrome 和 code 兑换都不携带代理，并且不修改后台账号保存的代理配置。
5. OAuth 兑换邮箱必须与锁定邮箱一致，写回前还会再次核对原账号。成功时调用专用 `apply-oauth-credentials` 接口更新同一个账号 ID，不调用创建接口或 `clear-error`。
6. 写回发生网络、超时、损坏响应或后台 `5xx` 时不会重放；只有查询到完整且匹配的最新凭据才确认成功，否则提示到后台人工核对。

同一时间只允许一个添加或重新授权任务。创建请求或重新授权写回开始发送后不能取消，避免把远端已执行的请求误认为已撤销。

## 后台登录安全

- 后台登录密码只存在于当次前端请求和本地服务调用栈中，不写入 SQLite、Keychain、日志或任务记录。
- 后台要求 TOTP 时，后台 `temp_token` 只保存在本地服务内存中；页面只获得一次性、五分钟过期的本地 attempt ID。
- 登录和 TOTP 的 POST 请求不会自动重试，避免重复登录尝试。
- 如果后台启用 Turnstile、腾讯/阿里验证码或强制登录协议，工具会在发送密码前停止并提示去后台处理，不伪造验证字段。
- 新登录只保存 Refresh Token。升级前已经保存的 Refresh Token 和 Access Token 仍可恢复；旧 Access Token 失效后会回到账号密码登录，不再提供手动 Token 输入。
- 点击“退出”会调用后台 logout 并清理 Keychain，但保留本地 bootstrap 会话，因此可以直接重新登录。

## 本地数据

SQLite 只保存脱敏任务状态、账号邮箱、所选配置、材料来源标记和最终后台账号摘要。后台密码、后台 TOTP、号池 bridge token、OpenAI 账号密码、2FA 密钥、生成的动态码、邮箱取件 Token、邮件正文、邮箱验证码、授权链接、代理密码和 OAuth 凭据不会写入 SQLite。

`<APP_DATA_DIR>/local-session-seed` 保存一个随机本地访问种子，文件权限固定为 `0600`，目录权限固定为 `0700`。它不包含后台账号、密码、Token、邮箱或 OAuth 数据，只用于让本地 Cookie 会话和 CSRF 在服务重启后保持一致。浏览器 cookie 最长保存一年，并在已验证的正常使用中滑动续期；这不会延长后台 Refresh Token 或 OpenAI OAuth 凭据的有效期，也不会把它们写入浏览器。删除该种子文件并重启服务可以主动撤销已有本地页面会话，之后需要重新使用单次入口确认。

原局域网 TLS 文件仍保留在 `<APP_DATA_DIR>/lan-tls`，当前 HTTP 模式不会读取它们。目录为 `0700`，CA 和服务器私钥为 `0600`，公开 CA 与服务器证书为 `0644`。将 `LAN_PROTOCOL` 改为 `https` 并保留现有证书路径即可恢复 HTTPS；IP 变化时仍必须重新签发包含新 IP SAN 的服务器证书。将 `LAN_ACCESS_ENABLED` 改为 `false` 并重新加载 LaunchAgent 可以关闭局域网入口，环回入口不受影响。

号池 bridge 只监听 `127.0.0.1`，使用独立 capability token 和精确邮箱接口，不复用号池网页登录 Cookie，也不读取号池数据库文件。默认 token 文件为 `~/Library/Application Support/up-icloud/account-pool-bridge-token`，必须保持仅当前用户可读。

自动模式不把号池材料发送到页面。手动备用模式仍按规范化账号邮箱或后台账号 ID 在当前网页内存隔离输入；这些遮罩字段不写入 `localStorage`、`sessionStorage`、SQLite、Keychain、日志或文件。单纯重启服务不会重载当前页面，因此页面内存仍在；刷新或关闭页面后不会恢复这些字段。

“允许重复创建”默认开启，因此同一个账号邮箱可以再次创建；它不表示不同邮箱可以共用一个收件链接。内置邮箱来源包括 `icloud.thefindnet.xyz`、`icloud-api.top`、`mail.mczero.top`、`blog.tx.sb`、`webmail.503.me`、`email.lzg666.icu/code/`、`ai100.my/mail/code/`、`icloud.olo.lat`、`assurivo.com`、`icloud.biubiu007.com`、`mail.ai1998.xyz`、`gptmail.wanmail.beer`、`li1329.asia`、`mailotp.xyhelper.ai`、`mail.776867.xyz`、`flysms.xyz`、`aigateway.online/api/v1/mail-pickup/`、`redeem.360desk.net/quick-mail/`、`191006.xyz/mailbox/`，以及动态 `*.trycloudflare.com/code/` 和 `*.trycloudflare.com/#otp=` 接码入口。`icloud-api.top` 同时支持 `/s/<访问凭据>/<邮箱>` 和 `/show/<访问凭据>/<邮箱>` 两种 HTTPS 页面；`webmail.503.me` 同时支持固定 `/webmail?mail=<邮箱>&pwd=<凭据>&limit=1&format=json` 接口，只接受邮箱身份匹配、用途明确且严格为六位数字的 OpenAI/ChatGPT 验证码；`email.lzg666.icu`、`ai100.my` 与动态 mail.com 接码入口使用相同的固定 JSON 协议，只接受邮箱身份匹配且能确认 OpenAI 或 ChatGPT 用途的六位验证码；动态 `#otp` 链接只把 fragment 凭据 POST 到同源固定 `/api/otp`；`mail.mczero.top` 使用 `/s/<访问凭据>/<邮箱>` 页面公开的固定 JSON 取件接口；360Desk 页面链接会使用当前任务邮箱请求固定的最近 60 分钟邮件接口；`191006.xyz/mailbox/<访问凭据>` 会核对页面邮箱身份，并同时支持旧邮件卡片和当前“最新邮件”的 `.mailbox + .subject + .content` 单封详情结构；号池中误放在邮箱 Token 字段的 `2fa.kim/2fa=<密钥>` 会作为密码登录用 2FA 密钥识别，不会作为邮箱接码链接使用；其他专用来源也只接受已经确认的固定 HTTPS origin、路径、参数和响应结构。带邮箱身份的响应必须与任务账号邮箱匹配。设置页仍可额外保存最多 20 个精确 HTTPS origin，但它们只使用 `/s/<访问凭据>/<邮箱>` 适配器，不会获得其他专用协议权限。

可信路径式链接会处理成对包装、复制空白、重复或末尾斜杠和邮箱单次编码，并允许最多三次保持完全相同 HTTPS origin 的规范跳转；访问凭据本身不改写。直连发生 DNS、连接或 TLS 错误时，服务只会回退到 macOS 当前启用的本机回环 HTTPS 代理，不接受远程或带认证的系统代理。未知 origin 在请求前返回 `MAIL_ORIGIN_UNTRUSTED`；跨域跳转、邮箱变化、额外路径、未知页面和用途不明的六位数字都会安全停止。`assurivo.com` 与 `icloud.biubiu007.com` 使用同一固定 JSON feed；其余新增来源分别使用 `/messages/` HTML、公开 inbox JSON、最新验证码 JSON、`/api/pickup` JSON 或带 Bearer 的 latest API，不进行跨协议猜测。

“任务记录”中的删除按钮只删除本地历史，不删除后台账号。设置页退出只退出本工具保存的后台会话，不修改 Chrome 或其他浏览器里的后台登录状态。

## 当前限制

- 后台登录和管理接口来自当前部署前端契约，不是公开版本化 API；后台升级后可能需要更新 `src/server/backend/`。
- 已有账号重新授权依赖当前部署的专用 `POST /admin/accounts/{id}/apply-oauth-credentials` 契约；接口或响应变化时会闭合失败，不会回退到创建或通用覆盖更新。
- 自动封号依赖当前部署的 `PUT /admin/accounts/{id}` 管理状态契约；必须在同一任务内达到设置的连续确认次数并唯一锁定账号，随后再用 `GET /admin/accounts/{id}` 读回确认。任何不确定结果都不会重放 `PUT`，需要到后台人工核对。
- 后台启用交互验证码或强制登录协议时，本版本不会自动完成该登录流程。
- 邮箱客户端支持固定 `mail.php`、Cloud Mailbox、Assurivo 兼容 feed，以及 AI1998、GPTMail、MailOTP、776867、FlySMS、360Desk Quick Mail、`icloud-api.top/show/`、`ai100.my/mail/code/` 和 `blog.tx.sb/fx.php` FirstMail 页面的专用适配器，同时保留内置或由设置页明确加入的 `/s/<访问凭据>/<邮箱>` HTTPS origin。Assurivo feed 与 FirstMail 页面固定只请求服务端最新 1 封，避免多个历史验证码形成冲突；`blog.tx.sb` 的两种链接格式互不混用。自定义 origin 不能自动兼容其他路径或私有 API；页面或 JSON 结构超出有限契约时仍会安全失败。验证码优先按可靠收件时间选择；只有代码明确保证最新优先的来源才允许连续两次首项稳定后的顺序兜底，不猜测验证码。
- OpenAI 页面变化可能触发人工接管。
- 密码 + 2FA 模式只支持 Base32 2FA 密钥，并按 SHA1、6 位、30 秒生成认证器动态码；不接受恢复码、短信验证码或完整 `otpauth://` URI。本机时间偏差会导致动态码无效。
- Chrome 无痕模式只隔离本次授权数据，不会绕过 Cloudflare、CAPTCHA、MFA 或其他安全验证。
- 代理出口由后台或动态订阅控制；工具保证同一任务使用同一解析配置，但不能保证动态上游始终使用相同出口 IP。
- 当前 LAN HTTP 不需要安装本机公开 CA；只有切回 `LAN_PROTOCOL=https` 时，各局域网设备才需要信任保留的 CA。远端浏览器页面可操作任务，但不会把 Chrome 授权窗口迁移到远端设备；当前监听配置依赖主机继续使用 `192.168.50.218/24`。

用户此前在对话中提供过包含邮箱取件密码的完整链接。真实任务验收前必须先更换该取件密码，不要继续使用已经暴露的值。
